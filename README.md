# depviz

Небольшая консольная программа на Java, которая показывает, от каких пакетов зависит пакет NuGet
(менеджер пакетов .NET), и рисует граф этих зависимостей. Зависимости программа достаёт сама,
без готовых менеджеров пакетов и сторонних библиотек.

Это практическая работа № 2 по «Конфигурационному управлению», вариант 4.
Сейчас готов первый этап: программа принимает настройки из командной строки, проверяет их
и печатает, что получилось.

## Настройки

Всё задаётся параметрами командной строки:

- `--package <имя>` – какой пакет анализировать. Обязательный параметр.
- `--package-version <версия>` – версия пакета, например `13.0.3`. Нужна всегда, кроме тестового режима.
- `--repo <адрес>` – откуда брать данные. По умолчанию это официальный репозиторий
  `https://api.nuget.org/v3-flatcontainer`. В тестовом режиме сюда пишется путь к файлу.
- `--test-mode` – работать не с настоящим репозиторием, а с тестовым файлом (о нём ниже).
- `--output <файл.svg>` – куда сохранить картинку с графом. По умолчанию `graph.svg`.
- `--ascii-tree` – дополнительно вывести зависимости деревом прямо в консоль.
- `--max-depth <n>` – насколько глубоко идти по зависимостям. По умолчанию 10.
- `--filter <подстрока>` – пропускать пакеты, в имени которых есть эта подстрока.
- `--help` – показать справку.

Значение можно писать через пробел (`--max-depth 3`) или через знак равно (`--max-depth=3`).

Если что-то задано неправильно, программа не падает, а объясняет, что не так, и завершается
с кодом 2. Например, она скажет, если забыли имя пакета, написали версию `latest`, указали
глубину `zero` или файл, которого нет.

### Тестовый репозиторий

Чтобы проверять программу без интернета, можно описать свой маленький «репозиторий» в текстовом
файле. Каждая строка – пакет и через двоеточие его зависимости. Пакеты называются заглавными
латинскими буквами, строки с `#` пропускаются:

```
A: B C
B: D
C: D
D:
```

Готовый пример лежит в [examples/basic.txt](examples/basic.txt).

## Сборка и тесты

Понадобятся Java 21 или новее и Maven (на macOS ставится командой `brew install maven`).

```bash
make build   # собрать программу
make test    # запустить тесты
make clean   # удалить всё, что получилось при сборке
```

Запускать удобнее всего через `./run.sh`: он сам пересоберёт программу, если код поменялся.

## Примеры

Посмотреть, какие настройки получились:

```bash
./run.sh --package Newtonsoft.Json --package-version 13.0.3 --ascii-tree --max-depth 3 --filter Test
```

```
Параметры запуска:
  package = Newtonsoft.Json
  package-version = 13.0.3
  repo = https://api.nuget.org/v3-flatcontainer
  test-mode = false
  output = graph.svg
  ascii-tree = true
  max-depth = 3
  filter = Test
```

То же самое с тестовым файлом:

```bash
./run.sh --test-mode --repo examples/basic.txt --package A
```

А так выглядят ошибки:

```
$ ./run.sh --package Newtonsoft.Json
Ошибка: Не задана версия пакета: укажите --package-version <версия>, например 13.0.3

$ ./run.sh --package Newtonsoft.Json --package-version 13.0.3 --max-depth zero
Ошибка: Максимальная глубина должна быть целым числом: 'zero'
```
